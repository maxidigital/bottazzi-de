V2X Framework.

A Java framework for sending and receiving connected-vehicle messages through roadside and on-board units, built for research at the German Aerospace Center (DLR).

RSU

What it does

Vehicles and traffic infrastructure talk to each other over V2X radio: position and speed, hazard warnings, detected objects, traffic-light phases and intersection maps. Talking to that radio directly means dealing with ASN.1 encodings, GeoNetworking and each hardware vendor's own interface.

The V2X Framework hides all of that. Its transceivers sit between the communication unit and the research applications: they decode incoming messages, translate them to the format each client needs (XML, JSON or a compact binary format) and encode outgoing ones for the radio. Clients can be Java programs or ROS nodes, connected over UDP, TCP or REST. Every message in and out is logged and can be forwarded to a backend for later analysis.

Its codec now also powers V2X Tools, the web version of the framework.

How it is built

  • Transceivers with pluggable gates and forwarders, configured per use case from a plain configuration file.
  • A hardware layer for communication units from several vendors, including Cohda, NEC Linkbird and Siemens, so the same application runs on different roadside units.
  • Message libraries from the ETSI standards in several versions: CAM, DENM, CPM, MAPEM/SPATEM, SREM, MCM and the ITS containers, with UPER encoding and XML/JSON views.
  • WinD, a small definition language with its own lexer, parser and ASN.1 parser, and a code generator that turns message definitions into versioned Maven libraries, ROS 1 and ROS 2 packages (messages and C++ sender/receiver nodes) and Protobuf schemas.
  • A backend subsystem that runs on the roadside unit and forwards every received message, untouched, to a Kafka broker.
  • Tools for field work and testing: message tester, decoder and random message generator, pcap parser, sniffer, GPS tools and a CPM fragmenter.
  • A multi-module Maven build with a GitLab CI pipeline that generates, tests and publishes the libraries.

My role

I designed and wrote the whole framework, including the WinD language and its code generator, and maintained it from 2019 to 2024 at the DLR Institute of Transportation Systems.

Stack
